# Skill: /rag-synthesize - Wide-Slice Topic Synthesis

**Purpose:** One topic, one deep retrieval (k up to 20), one structured written synthesis. Where `/rag-fanout` widens via many sub-queries, this deepens via one wide query - turning a scattered knowledge base into a readable brief with citations. Pattern 8 of `docs/rag-query-pattern-library.md`.
**Output:** A 2-3 page markdown brief (TL;DR → themed sections → open questions) with every claim cited to a source file, written to `--out` (default `/tmp/synthesis-<topic>.md`).
**Time to run:** 2-4 min.
**Cost:** Tier 1 in-chat $0. Scripted ~$0.40 (1 wide search + Sonnet synthesis of ~20 chunks). Hard-cap $2.

---

## HARD RULES

- **Closed-loop non-negotiable.** The wide search fires one `search_notes` + one `mark_retrieval` before return.
- **Every claim cites a source file.** A synthesis without per-claim citations is indistinguishable from a hallucination. No source = cut the claim or label it `[inference, not in corpus]`.
- **Synthesize, don't concatenate.** The output is a coherent brief that finds the THREADS across chunks - not 20 bullet points pasted in retrieval order. Group by theme, resolve overlaps, note contradictions.
- **Wide-slice cap = 20 chunks.** Above 20 the synthesis dilutes and cost climbs. `--k` max 20.
- **Recall gate.** If the wide search returns <3 chunks, the topic is thin in the corpus - say so plainly ("corpus has limited coverage of <topic>") rather than padding.
- **W1-W4:** W1 (frame query + vault) Haiku · W3 (synthesize) Sonnet · W4 (close loop + citation check) Haiku.

## When to use
- "Write up everything we know about chatbot pilots" / "synthesize our AI-ranking position" / "brief on our cutover playbook"
- Onboarding a new topic area into a single readable doc
- Pre-deck / pre-proposal source-gathering on one theme
- Converting scattered intel into a citeable internal reference

**Not for:** broad multi-angle questions (`/rag-fanout`); coverage audits (`/rag-skill-discovery`); narrow facts (Pattern 1).

## Input
**Required:** `<topic>` - the subject to synthesize.
**Optional:**
- `--vault <name>` (auto-routes per topic; override available)
- `--k <N>` chunks to pull (default 15, max 20)
- `--out <path>` (default `/tmp/synthesis-<topic-slug>.md`)
- `--audience <internal|client>` - if `client`, apply Rule 06 (no em dashes) + plain-English framing
- `--dry-run` show the query + vault + k, no fire

## Process

### Step 1 (W1, Haiku): Frame
Turn the topic into a wide search string. Pick the vault (operational → agency-operator; intel/courses → oo-brain; cross → null).

### Step 2 (W3): Wide retrieval
`mcp__search_notes(query=<topic>, k=<k>, vault=<vault>)`. Capture query_id + chunks (file_path, excerpt, score). If <3 chunks, note thin coverage.

### Step 3 (W3, Sonnet): Synthesize
```markdown
# <Topic> - Synthesis (<date>)
_Sources: <N> chunks from <vault>; generated by /rag-synthesize_

## TL;DR
<3-5 sentence distillation>

## <Theme 1>
<synthesized narrative> [source: <file>, "<excerpt>"]

## <Theme 2>
...

## Contradictions / tensions
<where sources disagree, named explicitly>

## Open questions / thin spots
<what the corpus does NOT cover - feeds skill/research gaps>

## Sources cited
- <file_path> (<n> chunks)
```
If `--audience client`: scan for em dashes (Rule 06), use plain English, drop internal jargon.

### Step 4 (W4, Haiku): Citation check + close loop
- Verify every section claim has a `[source: ...]`. Flag any uncited claim.
- `mark_retrieval(query_id, mark|warn|unsure)`: `mark` if chunks fed the brief.

### Step 5: Emit
Write to `--out`. Print: `SYNTHESIS: <topic> | <N> chunks | <themes> themes | <uncited> uncited claims | → <path> | closed-loop 1/1.`

## Quality Checks
- [ ] mark_retrieval fired for the search
- [ ] Every claim cited (or explicitly `[inference]`)
- [ ] Output is themed synthesis, not retrieval-order bullets
- [ ] Contradictions + thin spots sections present
- [ ] If `--audience client`: zero em dashes, plain English
- [ ] Thin coverage (<3 chunks) stated honestly, not padded

## Escalation rules
Escalate to Donal if: the topic returns thin coverage but is business-critical (research/build gap); sources contradict on something material (don't auto-pick a side); `--audience client` output would make a claim we can't verify (Rule 06 verify-before-cite - flag it).

## Cost note (Rule 15)
1 wide search + Sonnet over ~15-20 chunks ≈ $0.40. Hard-cap $2. Tier 1 in-chat $0.

## Composition
`composes_with_sesh: false`. Produces one document. If the synthesis seeds a multi-day effort, `/sesh new` separately and cite this brief as input.
