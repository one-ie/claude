# x402.md

> **HTTP 402 Payment Required, wired for agents.** The receive side is in production at `pay.one.ie` (`apps/one-core`). What's left is two thin SDK wrappers: `oneFetch()` (a better `fetch()` that auto-pays) and `createServer({ price, handler })` (a one-knob monetized endpoint). This doc is the source of truth for the wire format, what's shipped, and what's left.

**Mental model:** payment invisible at point of use. A dev calling `oneFetch(url)` should think *"I'm calling an API"*, not *"I'm paying for an API"*. Same for the server side: `createServer({ price: 0.01, handler })` should feel like Express with a price tag, not like a payments integration.

---

## One-line shape

> *Agent calls a paid endpoint → gets `402` with payment instructions → sends crypto on any of 7 chains → retries with `X-Payment-TX` header → endpoint verifies on-chain → returns `200` (and a signed coupon if cross-chain).*

No card networks. No signup. No merchant account. Stateless — the worker stores nothing; chain is the source of truth.

## What's shipped (don't rebuild)

### Receive side — production at `pay.one.ie`

| Piece | File | Lines | What it does |
| --- | --- | --- | --- |
| **Hono middleware** | `apps/one-core/backend/src/x402.ts` | 198 | Issues 402 challenge with payment headers; verifies `X-Payment-TX` on retry; sets `c.var.x402Payment` for downstream handlers |
| **`x402_quote` protocol** | `apps/one-core/backend/src/protocol/handlers/x402.ts` | (within 416) | Returns `payAmount`, `treasury`, `usdcContract`, `expiresAt` for a token amount + chain |
| **`x402_claim` protocol** | same file | (within 416) | Verifies payment tx on source chain; signs coupon for destination chain (Ed25519 Sui · ECDSA EVM · Solana); returns `success + payment + claim.coupon` |
| **Chain verifiers** | `apps/one-core/backend/src/chains/{sui,evm,solana,bitcoin}.ts` | — | RPC-only, read-only. `verifyEvmTransaction` + `verifyUsdcPayment` (ERC-20) for Base/ETH/ARB/OPT |
| **CLI tester** | `apps/one-core/tools/payment/x402.ts` | 102 | `bun run x402.ts --tx <hash> --chain SUI` — challenge, retry-with-proof |
| **Stateless coupon signer** | `apps/one-core/backend/src/signer.ts` | — | `signForEVM` / `signForSui` / `signForSolana` — deterministic; same TX → same coupon |
| **On-chain replay defense** | `contracts/sui/`, `contracts/evm/` | — | ReplayTracker + signature-bound claims; worker can't double-spend (no key access to treasury) |

**Chains supported**: SUI · ETH · BASE · ARB · OPT · SOL · BTC. **Currencies**: native + USDC (EVM chains only, auto-detected).

### Treasury fee

50bps to Treasury, enforced on-chain (Move + Solidity). Worker does not collect, cannot collect.

## The wire format

### 402 challenge (server → caller)

```http
HTTP/1.1 402 Payment Required
X-Payment-Amount: 0.000123          # in selected chain's native units (or USDC)
X-Payment-Currency: SUI             # ETH / BASE / SOL / SUI / BTC / USDC
X-Payment-Address: 0x…              # treasury address for that chain
X-Payment-Chains: SUI,ETH,BASE,SOL  # all acceptable chains for this resource
Content-Type: application/json

{
  "status": "payment_required",
  "product": "translate-skill",
  "amountUsd": 0.05,
  "payOptions": [
    { "chain": "SUI", "currency": "SUI", "amount": 0.0123, "address": "0x…" },
    { "chain": "BASE", "currency": "BASE", "amount": 0.0000087, "address": "0x…" }
  ],
  "instructions": "Send the specified amount, then retry with X-Payment-TX and X-Payment-Chain headers."
}
```

### Retry with proof (caller → server)

```http
GET /api/skill/translate HTTP/1.1
X-Payment-TX: 0xabc123…
X-Payment-Chain: BASE
```

Server verifies via RPC, ensures `valueUsd ≥ usdTarget × 0.99` (price-drift buffer), proceeds with handler.

### Cross-chain claim (optional)

For payments where source ≠ destination chain: caller hits `POST /` with `{ protocol: "x402_claim", data: { paymentTx, paymentChain, userAddress, destination } }` → receives a signed coupon → claims on destination contract. Used for "pay on Base, mint on Sui."

## What's NOT shipped — the actual gap

### Send side — `oneFetch()` SDK function (Wave 0)

**Status:** ☐ — the buyer half of Wave 0.

**File to create:** `one-ie/one/packages/sdk/src/fetch.ts`

**What it does:** drop-in `fetch()` replacement. If the response is 402, auto-discover payment options, pay on the cheapest available chain, retry with proof. Dev never sees `X-Payment-*` headers.

```typescript
import { oneFetch } from "@oneie/sdk"

// That's it. No setup.
const res = await oneFetch("https://pay.one.ie/api/skill/translate?q=hello")
const text = await res.text()  // "hola"
```

**Optional config (power users):**

```typescript
import { createAgent } from "@oneie/sdk"

const agent = createAgent({
  name: "research-bot",
  maxSpendPerCall: 0.10,    // refuse if quote > $0.10
  dailyBudget: 5.00,        // $5/day cap
  preferredChain: "BASE",   // or "AUTO" (default)
  network: "testnet",       // or "mainnet" — explicit, never silent
})

const res = await agent.fetch(url)
```

**Default behavior (no config):**
- testnet, ephemeral local seed at `~/.oneie/dev-wallet`
- `maxSpendPerCall: 0.05`, `dailyBudget: 1.00`
- chain auto-selected (cheapest gas, fastest confirmation)
- silent retries; only errors surface

**Three error types — that's all:**

```typescript
PaymentError          // quote acceptable but tx failed
BudgetExceededError   // quote > maxSpendPerCall or > dailyBudget
NetworkError          // RPC down, endpoint unreachable
```

**Debug mode:**

```typescript
oneFetch(url, { debug: true })
// → 402 received ($0.03)
// → Paying via BASE (USDC)
// → TX: 0xabc123…
// → Retry success (200)
```

### Receive side — `createServer()` SDK wrapper (Wave 0)

**Status:** ☐ — the seller half of Wave 0.

**File to create:** `one-ie/one/packages/sdk/src/server.ts`

**What it does:** wraps the existing `apps/one-core` Hono middleware in a one-knob API. Dev sets a price and writes a handler; SDK does the rest (treasury wallet, 402 challenge, on-chain verification, signed coupon).

```typescript
import { createServer } from "@oneie/sdk/server"

createServer({
  price: 0.01,  // USD per request
  handler: async (req) => {
    const { input } = await req.json()
    return { result: input.toUpperCase() }
  }
})
// → "Agent live at https://pay.one.ie/api/agent/abc123"
// → "Earnings: $0.00"
```

**Default behavior (no config):**
- testnet treasury auto-generated, seed at `~/.oneie/dev-treasury`
- endpoint registered at `pay.one.ie/api/agent/<uid>` (or local for self-host)
- earnings counter prints to console on each paid request
- `--mainnet` flag (or `ONEIE_NETWORK=mainnet`) required for real money

**One knob, that's it:**

```typescript
{ price: 0.01 }   // USD; everything else has sane defaults
```

### Trust ramp (non-negotiable)

Both `oneFetch()` and `createServer()` default to **testnet**. Real money requires explicit opt-in:

```bash
# default — spends 0 real $
node index.js

# explicit mainnet — required to spend real
ONEIE_NETWORK=mainnet node index.js
# or
node index.js --mainnet
```

The first time a dev runs an `@oneie/sdk` script, money does not leave their wallet. Period. This is load-bearing for adoption — surprise auto-spends are a trust cliff.

## Threat model row

| What it defends | How | What it accepts |
| --- | --- | --- |
| **Worker stealing funds** | Worker holds zero treasury keys; only signs deterministic coupons | If signing key leaks, attacker can forge claims on the destination chain (mitigation: rotate, multisig — Phase 2) |
| **Replay** | On-chain `ReplayTracker` (Sui) / nonce-bound claims (EVM) | Worker is stateless — relies on chain enforcement |
| **Payment underpayment** | `valueUsd ≥ usdTarget × 0.99` check + per-chain price feed | If price feed fails, server returns 402 again (worst case = no service, not theft) |
| **Quote staleness** | `expiresAt = now + 5min` | Caller paying past expiry will get rejected; safe-fail |
| **Wrong chain in retry** | `supportedChains.includes(chain)` check, 400 if not | Caller must read `X-Payment-Chains` |
| **Bogus TX hash** | RPC-verified each retry — no caching of unverified hashes | RPC outage → 402 again |
| **Agent paying above intent** | `payRequest({ maxUsd })` must reject if quote exceeds budget | Currently caller responsibility (SDK client must enforce) |

## The 5 design choices that matter

1. **Stateless worker.** All state on-chain. The worker can be killed and rebuilt with no data loss; the only thing it needs is the signing key.
2. **Deterministic coupons.** Same `paymentTx` always produces the same signed coupon. No idempotency layer required; replay defense is on-chain.
3. **Multi-chain by tx-hash, not by intent.** Caller picks chain at retry time. The `payOptions` array is a menu, not a commitment.
4. **USDC where it makes sense.** EVM USDC verification exists today; Sui/Solana USDC are TODOs. We don't pretend "stablecoin everywhere" until it's true.
5. **No platform account required.** Treasury is a chain address. Anyone can deploy their own worker pointed at their own treasury.

## Open questions

- **Sponsored x402** — should the agent pay gas, or should the resource-owner sponsor it? Today: agent pays. Phase 2: optional sponsorship via the sponsor Worker (shape from `enoki-play`).
- **Quote refresh** — 5min `expiresAt` is plenty for humans; for agents in tight loops, do we want a streaming price feed? Probably not until Wave 2.
- **Microsecond payments** — current floor is ~$0.001 (gas-limited on EVM, fine on Sui/SOL). For sub-cent payments at scale, batching or state-channel layer is Phase 3.
